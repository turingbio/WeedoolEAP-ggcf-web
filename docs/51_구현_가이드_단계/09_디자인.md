# 9. 디자인

목표: 8번에서 고정한 구성과 문구 위에 위둘 브랜드 디자인을 입힌다. 자산을 고르고, 시각 방향을 정하고, 토큰과 공통 컴포넌트를 만든 뒤 `/verify`와 `/welcome`에 차례로 적용한다. 정적 화면이 끝나면 모션과 엣지 케이스 화면을 더하고, 접근성을 점검해 DESIGN.md로 정리한다.

- 기준 문서: `docs/42_디자인_배포_인계.md`, `docs/43_디자인_배포_seed.yaml`
- 정본 자산: `docs/40_디자인_자산/`
- 작업 도구: impeccable (`shape`, `critique`, `audit`, `polish`, `document`)
- 작업 분담: 디자인·스타일 코드는 Claude가 구현까지 한다. 이 단계만 "코드는 사용자가 쓴다"는 원칙의 예외다

## 9-2. 작업 순서

```
자산 선별 ──▶ 시각 방향 ──▶ 토큰 ──▶ 공통 컴포넌트 ──▶ /verify ──▶ /welcome
                                                                     │
      DESIGN.md ◀── 점검(critique·audit·polish) ◀── 엣지 케이스 ◀── 모션
```

앞 단계가 끝나야 다음 단계의 판단 근거가 생긴다. 토큰 없이 컴포넌트를 만들면 값을 컴포넌트마다 따로 적게 되고, 정적 화면이 끝나기 전에 모션을 넣으면 레이아웃이 바뀔 때마다 모션도 다시 맞춰야 한다.

| 단계 | 산출물             | 끝났다는 기준                            |
| ---- | ------------------ | ---------------------------------------- |
| 9-3  | 자산 목록          | 목록의 파일이 `40_디자인_자산/`에 있다   |
| 9-4  | 시안 비교 기록     | 2~3안 중 하나를 사용자가 골랐다          |
| 9-5  | `globals.css` 토큰 | 임시 토큰이 모두 사라졌다                |
| 9-6  | 공통 컴포넌트      | 상태별 모양이 모두 정해졌다              |
| 9-7  | 화면 적용          | 375px, 1440px에서 모든 화면이 렌더링된다 |
| 9-8  | 모션               | reduced-motion 대체 표현까지 있다        |
| 9-9  | 엣지 케이스 화면   | 4종 모두 mock 입력으로 재현된다          |
| 9-10 | 접근성 검증 리포트 | 미해결 위반이 0건이다                    |
| 9-11 | DESIGN.md          | 토큰 값이 `globals.css`와 같다           |

## 9-3. Figma 자산 선별

Figma 원본은 파일이 크고 수가 많아 통째로 읽지 않는다. 필요한 것만 골라 받는다.

### 무엇을 받을지 정하는 기준

앱 디자인을 웹으로 옮길 때 필요한 것은 네 종류다.

| 종류   | 예                       | 없으면 생기는 일                          |
| ------ | ------------------------ | ----------------------------------------- |
| 정체성 | 로고, 캐릭터             | 웹과 앱이 다른 회사처럼 보인다            |
| 규격   | 색, 타이포, 반경, 그림자 | 눈대중으로 정한 값이 화면마다 어긋난다    |
| 형태   | 버튼, 입력창, 카드       | 색은 같은데 모양이 달라 어색하다          |
| 콘텐츠 | 앱 화면 캡처             | 빈 상자로 남아 레이아웃을 확정하지 못한다 |

#### 판단 규칙

- **값으로 받을 수 있으면 파일로 받지 않는다.** 색은 `41_앱_색상.md`에 이미 헥사값으로 있으니 Figma 색 변수를 다시 받지 않는다. 타이포도 파일이 아니라 숫자 목록으로 받는다. 파일이 늘어날수록 어느 것이 정본인지 흐려진다.
- **크기가 변하는 자리에 쓰는 것은 벡터로 받는다.** 로고는 Header에서 작게, `/verify`에서 크게, 계정 PNG에서 또 다른 크기로 쓰인다. 래스터로 받으면 가장 큰 자리에 맞춰야 하고, 나머지 자리에서는 파일만 무거워진다.

### 목록

| #   | 자산             | 규격                                  | 둘 곳                                | 쓰이는 곳                   |
| --- | ---------------- | ------------------------------------- | ------------------------------------ | --------------------------- |
| 1   | 로고 가로형      | SVG                                   | `40_디자인_자산/brand/logo-full.svg` | Header, `/verify`, 계정 PNG |
| 2   | 로고 아이콘형    | SVG                                   | `40_디자인_자산/brand/logo-icon.svg` | favicon, 좁은 화면 Header   |
| 3   | 타이포 규격      | 서체 이름, 단계별 크기·굵기·행간      | `40_디자인_자산/타이포.md`           | `globals.css` 타이포 토큰   |
| 4   | 버튼·입력창·카드 | 각 1종, 상태별(기본·눌림·비활성) 화면 | `40_디자인_자산/components/`         | 9-6 공통 컴포넌트           |
| 5   | 반경·그림자      | 숫자 목록                             | `40_디자인_자산/타이포.md`에 함께    | `globals.css`               |
| 6   | 캐릭터 포즈      | PNG 2배수, 배경 투명                  | `40_디자인_자산/character/`          | Hero, 익명성, 오류 화면     |
| 7   | 앱 화면 캡처     | PNG, 세로 9:16, 폭 750px 이상         | `40_디자인_자산/app/`                | 05 `process` 다섯 단계      |

로고가 SVG여야 하는 이유는 계정 PNG에도 있다. `html-to-image`는 화면을 다시 그려 PNG를 만드는데, 원본 해상도가 낮으면 저장된 이미지에서 로고만 흐리게 남는다.

Figma 링크를 주면 Claude가 Figma MCP로 노드 목록을 읽고 위 표에 맞는 노드를 골라 제안한다. Figma MCP는 인증이 필요하다. 연결되지 않으면 `claude mcp`로 인증부터 한다.

## 9-4. 시각 방향 정하기

### 화면 성격 먼저 나누기

impeccable은 화면의 목적에 따라 판단 기준을 바꾼다. 두 화면은 목적이 다르다.

| 화면       | 방문자가 하는 일              | 성격     | 우선하는 것              |
| ---------- | ----------------------------- | -------- | ------------------------ |
| `/verify`  | 기관코드를 넣고 통과한다      | Operate  | 빠른 인지, 오류의 명확함 |
| `/welcome` | 읽고, 안심하고, 계정을 받는다 | Persuade | 신뢰, 리듬, 섹션 간 위계 |

`/verify`에 랜딩의 장식을 그대로 가져오면 입력칸이 묻힌다. 두 화면은 같은 토큰을 쓰되 밀도를 다르게 둔다.

### 시안 만들기

```
/impeccable shape /welcome
```

`shape`는 `PRODUCT.md`와 `docs/21_UX_문구.md`를 읽고 시각 방향을 2~3안 만든다. 각 안은 이름, 한 줄 요약, 대표 화면(Hero와 03 익명성) 두 장으로 비교한다. 섹션 전체를 그리지 않는다. 두 섹션이면 방향 차이가 드러나고, 전체를 그리면 고르기 전에 하루가 간다.

### 시안 비교 기록

고른 결과는 `docs/44_시안_비교.md`에 남긴다. 나중에 "왜 이 색을 주색으로 썼나"를 물을 때 이 문서가 답이 된다.

```markdown
| 안  | 이름   | 요약                            | runway 대비          | 산타 토익 대비 | 선택 |
| --- | ------ | ------------------------------- | -------------------- | -------------- | ---- |
| A   | 편지지 | 흰 바탕, 넓은 여백, 캐릭터 강조 | 여백은 비슷, 더 따뜻 | 라벨 구조 같음 | ✓    |
| B   | …      | …                               | …                    | …              |      |

고른 이유:
버리는 안에서 가져올 것:
```

## 9-5. 디자인 토큰

### 색

`41_앱_색상.md`의 값을 역할별로 골라 옮긴다. 모든 값을 토큰으로 만들지 않는다. 쓰지 않는 토큰은 나중에 누군가 "이것도 써도 되나" 고민하게 만든다.

| 토큰           | 값          | 출처                   | 흰 바탕 대비 | 쓰는 곳                    |
| -------------- | ----------- | ---------------------- | ------------ | -------------------------- |
| `brand`        | `#0066FF`   | Primary Heavy          | 4.83         | 주 버튼 배경, 링크, 포커스 |
| `brand-strong` | `#0052CC`   | Palette Primary 700    | 6.82         | 버튼 눌림                  |
| `brand-soft`   | `#EDF3FA`   | Background Elevated    | —            | 강조 섹션 배경             |
| `ink`          | `#1D1F27`   | Label secondary        | 16.44        | 제목, 본문                 |
| `muted`        | `#5A5C63`   | Label primary          | 6.68         | 설명, 보조 문장            |
| `line`         | `#70737C38` | Line Normal            | —            | 구분선, 카드 테두리        |
| `surface`      | `#F8F8FA`   | Background Alternative | —            | 카드 배경                  |
| `danger`       | `#C20A0A`   | Palette Error 700      | 6.28         | 오류 문장                  |

골라낸 기준이 몇 가지 있다.

- **주색은 Normal(`#008EFF`)이 아니라 Heavy(`#0066FF`)를 쓴다.** Normal은 흰 바탕 대비가 3.33이라 흰 글씨 버튼과 본문 링크에 쓰면 4.5:1을 넘지 못한다. Normal은 24px 이상 큰 제목의 강조나 일러스트처럼 글자가 아닌 곳에만 쓴다.
- **오류색은 Negative(`#F64C4C`)가 아니라 Error 700(`#C20A0A`)을 쓴다.** Negative는 대비가 3.47이다. 아이콘이나 테두리처럼 3:1이면 되는 곳에는 Negative를 써도 된다.
- **Label 이름과 명도가 뒤바뀌어 있다.** `41_앱_색상.md`에서 가장 진한 글자색이 `secondary`(`#1D1F27`)이고 `primary`(`#5A5C63`)는 그보다 옅다. 토큰 이름은 앱 이름을 따르지 않고 역할(`ink`, `muted`)로 짓는다.
- **tertiary(`#878A93`)와 Assistive(`#AEB0B6`)는 글자에 쓰지 않는다.** 대비가 각각 3.45, 2.17이다.

브랜드 색을 지키느라 4.5:1을 넘지 못하는 자리가 생기면 억지로 색을 바꾸지 말고, 위치와 사유를 9-10의 리포트에 적는다. 수락 기준은 브랜드 색 사유로 기록된 위반만 예외로 인정한다.

### 타이포·간격·반경

서체는 Pretendard Variable을 쓴다. 단계별 크기는 9-3의 타이포 규격을 받아 정하되, 아래 최솟값은 규격과 상관없이 지킨다. 주 사용자에 고연령층이 있어서 정한 값이다.

| 항목      | 최솟값 |
| --------- | ------ |
| 본문 글자 | 16px   |
| 버튼 글자 | 20px   |
| 터치 영역 | 48px   |

### `globals.css`

토큰은 Tailwind 4의 `@theme`에 둔다. 여기 적은 이름이 그대로 `bg-brand`, `text-muted` 같은 클래스가 된다.

```css
@import 'tailwindcss';

@theme {
  --color-brand: #0066ff;
  --color-brand-strong: #0052cc;
  --color-brand-soft: #edf3fa;
  --color-ink: #1d1f27;
  --color-muted: #5a5c63;
  --color-line: #70737c38;
  --color-surface: #f8f8fa;
  --color-danger: #c20a0a;

  --font-sans:
    var(--font-app), system-ui, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif;

  --text-body: 1.125rem;
  --text-body--line-height: 1.7;
  --text-button: 1.25rem;
  --text-title: 1.75rem;
  --text-title--line-height: 1.35;

  --spacing-touch: 3rem;

  --radius-card: 1rem;
  --radius-button: 0.75rem;
}

html {
  -webkit-text-size-adjust: 100%;
}

body {
  word-break: keep-all;
}
```

타이포 크기와 반경은 9-3에서 규격이 오면 그 값으로 바꾼다. 위 값은 최솟값을 지키는 출발점이다.

## 9-6. 공통 컴포넌트

화면보다 컴포넌트를 먼저 만든다. 버튼 하나가 네 섹션에 쓰이니, 섹션마다 스타일을 적으면 같은 버튼이 네 가지 모양이 된다.

| 컴포넌트         | 파일                                    | 상태                                   |
| ---------------- | --------------------------------------- | -------------------------------------- |
| `Button`         | `src/components/ui/Button.tsx`          | 기본, 호버, 눌림, 포커스, 비활성, 로딩 |
| `ButtonLink`     | `src/components/ui/Button.tsx`          | 기본, 호버, 눌림, 포커스               |
| `SectionWrapper` | `src/components/SectionWrapper.tsx`     | 라벨 있음/없음, 설명 있음/없음         |
| `Card`           | `src/components/ui/Card.tsx`            | 기본                                   |
| 기관코드 입력창  | `src/features/org-code/OrgCodeForm.tsx` | 기본, 포커스, 오류, 확인 중            |

모든 상호작용 요소는 포커스가 보여야 한다. 마우스로 쓸 때는 보이지 않다가 키보드로 옮겨 올 때만 나타나도록 `focus-visible`을 쓴다.

```tsx
const baseClass =
  'inline-flex min-h-touch w-full items-center justify-center rounded-button px-6 text-button font-bold ' +
  'focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand ' +
  'disabled:cursor-not-allowed disabled:opacity-50';
```

`SectionWrapper`는 8번에서 정한 세 층(라벨·제목·설명)을 한 곳에서 그린다. 섹션 컴포넌트가 제목 크기나 라벨 색을 따로 정하지 않게 하려는 것이다.

## 9-7. 화면 적용

`/verify` → Header → 01~07 → Footer 순으로 적용한다. 한 화면을 끝낼 때마다 375px와 1440px에서 확인한다.

| 화면·섹션      | 디자인에서 볼 것                                                  |
| -------------- | ----------------------------------------------------------------- |
| `/verify`      | 입력칸이 첫눈에 들어오는가. 오류 문장이 입력칸 바로 아래에 붙는가 |
| Header         | 로고만 있다. 스크롤해도 높이가 변하지 않는다                      |
| 01 `hero`      | 편지봉투(`images/weedool-envelope.png`)가 중심. 스토어 버튼 두 개 |
| 02 `intro`     | 라벨·제목·설명 위계. 기능 카드 2×2(모바일 1열)                    |
| 03 `anonymity` | 카드 3개. 모바일에서 세로로 쌓인다                                |
| 04 `account`   | 발급 전·중·후·오류 네 상태의 높이 차이로 화면이 튀지 않는가       |
| 05 `process`   | 캡처 5장 가로 배치. 모바일에서 가로 스크롤 대신 세로 목록         |
| 06 `install`   | QR 두 개와 스토어 버튼. 모바일에서는 QR보다 버튼이 먼저           |
| 07 `faq`       | 질문을 누르면 답이 펼쳐진다. 펼친 질문이 눈에 띈다                |
| Footer         | 전화·메일 링크가 48px 터치 영역을 갖는다                          |

06 설치에서 모바일에 버튼을 먼저 두는 것은, 휴대폰으로 들어온 사람이 자기 화면의 QR을 찍을 수 없기 때문이다.

## 9-8. 인터랙션·모션

정적 화면이 모두 끝난 뒤에 넣는다.

```
/impeccable animate /welcome
```

| 대상          | 움직임                          | reduced-motion일 때                     |
| ------------- | ------------------------------- | --------------------------------------- |
| Hero 편지봉투 | 봉투가 열리며 편지가 올라온다   | 봉투가 열린 마지막 모습을 정지 이미지로 |
| 섹션 진입     | 아래에서 살짝 떠오르며 나타난다 | 바로 보인다                             |
| 버튼          | 눌림 시 색이 진해진다           | 색 변화만 유지한다                      |
| 계정 발급 중  | 버튼 안 로딩 표시               | 문구(`계정을 생성하고 있어요`)만        |
| FAQ           | 답이 펼쳐진다                   | 바로 펼쳐진다                           |

움직임은 모두 한 곳에서 끌 수 있어야 한다. 섹션마다 따로 막으면 하나를 빠뜨린다.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Hero 편지봉투는 이것만으로는 부족하다. 애니메이션을 짧게 끊으면 첫 프레임(닫힌 봉투)에서 멈출 수 있어서, reduced-motion일 때는 애니메이션 대신 마지막 프레임 이미지를 보여 준다.

## 9-9. 엣지 케이스 화면

네 가지 실패 상태를 화면으로 만들고, mock에서 언제든 다시 볼 수 있게 한다. 재현 방법이 없으면 디자인을 확인할 때마다 서버 오류를 기다려야 한다.

| 상태              | 화면                        | 문구 위치                           | mock 재현 방법                               |
| ----------------- | --------------------------- | ----------------------------------- | -------------------------------------------- |
| 기관코드 오류     | `/verify` 입력칸 아래       | `common.ts` `errors.invalidOrgCode` | `A1B2C3`이 아닌 6글자 입력                   |
| 네트워크 오류     | `/verify` 입력칸 아래       | `common.ts` `errors.network`        | 기관코드 `ERR500` 입력                       |
| 계정 발급 실패    | 04 `account` 버튼 위        | `account/content.ts` `issueError`   | `.env.local`에 `NEXT_PUBLIC_MOCK_FAIL=issue` |
| PNG 다운로드 실패 | 04 `account` 계정 카드 아래 | `credential-image/content.ts`       | `.env.local`에 `NEXT_PUBLIC_MOCK_FAIL=png`   |

`NEXT_PUBLIC_MOCK_FAIL`은 이 단계에서 새로 만드는 mock 설정이다. `src/lib/api/mock/accounts.ts`와 `downloadCredentialPng.ts`가 이 값을 읽어 일부러 실패한다. 실제 서버 모드(`NEXT_PUBLIC_USE_MOCK=false`)에서는 읽지 않는다.

PNG 다운로드 실패 문구는 아직 `content.ts`에 없다. 문구를 새로 정해야 하므로 `docs/21_UX_문구.md`에 먼저 넣고 나서 코드로 옮긴다. 8번에서 정한 순서(문서 → 코드)를 여기서도 지킨다.

## 9-10. 점검과 접근성 검증 리포트

정적 화면, 모션, 엣지 케이스까지 모두 들어간 뒤에 한 번에 점검한다.

```
/impeccable critique /welcome
/impeccable audit
/impeccable polish
```

`critique`는 위계와 흐름을, `audit`은 대비·키보드·반응형 같은 기술 항목을 본다. 두 결과를 모아 `polish`로 한꺼번에 고친다. 항목마다 고치고 다시 점검하기를 반복하면 끝이 나지 않는다. 모바일과 데스크톱 스크린샷을 한 번에 찍어 보고, 고친 뒤 한 번만 더 확인한다.

impeccable의 자동 탐지 훅은 설정에 등록되어 있지 않다. 파일을 고쳐도 저절로 점검하지 않으니 `audit`을 직접 실행한다.

| 항목           | 기준                                       |
| -------------- | ------------------------------------------ |
| 텍스트 대비    | 4.5:1 이상. 24px 이상 큰 글자는 3:1 이상   |
| 키보드 조작    | Tab만으로 `/verify` → 계정 발급 → 설치까지 |
| 포커스 표시    | 모든 상호작용 요소에서 보인다              |
| 글자 크기      | 본문 16px, 버튼 20px 이상                  |
| 터치 영역      | 48px 이상                                  |
| reduced-motion | 9-8 표의 대체 표현이 나온다                |

결과는 `docs/45_접근성_검증.md`에 남긴다. 미해결 위반은 0건이어야 하고, 브랜드 색 때문에 남긴 위반만 위치와 사유를 적어 예외로 둔다. 10번 실기기 점검에서 확인하는 PNG 자동 다운로드 결과도 이 리포트의 배포 확인 기록에 함께 적는다.

## 9-11. DESIGN.md

```
/impeccable document
```

`document`는 구현된 코드에서 디자인 시스템을 뽑아 저장소 루트에 `DESIGN.md`를 만든다. 계획이 아니라 실제로 들어간 값을 기록하는 것이 목적이라 가장 마지막에 한다. 만든 뒤에는 `DESIGN.md`의 색·타이포·반경 값이 `globals.css`의 `@theme`와 같은지 확인한다. 다르면 코드가 맞고 문서가 틀린 것이니 `document`를 다시 돌린다.
