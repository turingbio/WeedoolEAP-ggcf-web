# 9. 디자인

목표: 8번에서 고정한 구성과 문구 위에 위둘 브랜드 디자인을 입힌다. 시각 방향을 고르고, 토큰을 정하고, 공통 컴포넌트부터 섹션까지 순서대로 적용한 뒤 모션과 오류 화면까지 만든다.

근거 문서는 `docs/12_디자인_배포_인계.md`와 `docs/13_디자인_배포_seed.yaml`이다.

참고 사이트는 runway와 산타 토익 둘로 한정한다. runway에서는 여백과 대비를, 산타 토익에서는 섹션 제목의 라벨·제목·설명 구조와 학습 앱다운 친근함을 본다.

## 9-2. 필수 Figma 에셋 목록

Figma 원본은 파일이 크고 수가 많아 통째로 읽지 않는다. 필요한 것만 골라 받는다.

### 무엇을 받을지 정하는 기준

디자인 시스템에서 웹으로 넘어올 때 필요한 것은 네 가지뿐이다. 이 분류는 위둘만이 아니라 앱 디자인을 웹으로 옮기는 모든 작업에 쓸 수 있다.

| 종류 | 왜 필요한가 | 없으면 생기는 일 |
| --- | --- | --- |
| **정체성** 로고, 캐릭터 | 같은 브랜드임을 알아보게 하는 최소 단위 | 웹과 앱이 다른 회사처럼 보인다 |
| **규격** 색, 타이포, 반경, 그림자 | 값으로 옮겨 적을 수 있는 규칙 | 눈대중으로 정한 값이 화면마다 어긋난다 |
| **형태** 버튼, 입력창, 카드 | 값만으로는 못 옮기는 생김새와 상태 변화 | 색은 같은데 모양이 달라 어색하다 |
| **콘텐츠** 앱 화면 캡처 | 화면에 실제로 들어갈 내용물 | 빈 상자로 남아 레이아웃을 확정하지 못한다 |

여기서 두 가지 판단 규칙이 나온다.

**값으로 받을 수 있으면 파일로 받지 않는다.** 색은 `41_앱_색상.md`에 이미 헥사값으로 있으니 Figma 색 변수를 다시 받을 이유가 없다. 타이포도 마찬가지라 파일이 아니라 숫자 목록으로 받는다. 파일이 늘어날수록 어느 것이 정본인지 흐려진다.

**크기가 변하는 자리에 쓰는 것은 벡터로 받는다.** 로고는 Header에서 작게, `/verify`에서 크게, 계정 PNG에서 또 다르게 쓰인다. 래스터로 받으면 가장 큰 자리에 맞춰야 하고, 그러면 나머지 자리에서 파일이 무거워진다.

아래 목록에서 왼쪽이 자산, 오른쪽이 그 자산이 없으면 막히는 화면이다.

### A. 필수 — 없으면 시안을 시작할 수 없다

| # | 자산 | 규격 | 둘 곳 | 쓰이는 곳 |
| --- | --- | --- | --- | --- |
| A1 | 로고 가로형 | SVG | `42_디자인_자산/brand/logo-full.svg` | Header, /verify 상단, 계정 PNG |
| A2 | 로고 아이콘형 | SVG | `42_디자인_자산/brand/logo-icon.svg` | favicon, 좁은 화면 Header |
| A3 | 앱 화면 캡처 5장 | PNG, 세로 9:16, 폭 750px 이상 | `42_디자인_자산/app/01_로그인.png` … `05_리포트.png` | 05 `process` 다섯 단계 |
| A4 | 타이포 규격 | 글꼴 이름, 크기·굵기·행간 단계 | `43_타이포.md` | `globals.css` 타이포 토큰 전부 |

**A1·A2가 SVG여야 하는 이유.** 지금 있는 `logo-full.webp`는 래스터라 Header에서 확대하면 가장자리가 뭉개진다. 계정 PNG는 `html-to-image`가 화면을 다시 그려 만드는데, 이때 원본 해상도가 낮으면 저장된 이미지에서 로고만 흐리게 남는다.

**A3가 5장인 이유.** 21번 문서 05 섹션이 로그인, 자가진단, BA 수행, AI 상담, 리포트 순서로 고정되어 있다. 단계마다 한 장씩 필요하고, 순서가 정해져 있으니 파일 이름에 번호를 붙여 받는다. 현재는 `aspect-[9/16]` 빈 상자로 자리만 잡아 둔 상태다.

**A4를 받는 법.** Figma 왼쪽 패널의 텍스트 스타일 목록을 펼쳐 캡처하거나, 아래 형태로 적어 주면 된다. 값만 있으면 되고 형식은 자유다.

```
글꼴: Pretendard Variable
Display  32 / 42  Bold
Title    24 / 34  Bold
Body     18 / 28  Regular
Caption  14 / 20  Regular
자간: -0.02em
```

### B. 권장 — 없으면 앱과 미세하게 달라진다

| # | 자산 | 규격 | 둘 곳 | 쓰이는 곳 |
| --- | --- | --- | --- | --- |
| B1 | 버튼 상태 | PNG. 기본·눌림·비활성 | `42_디자인_자산/components/button.png` | 공통 Button |
| B2 | 입력창 상태 | PNG. 기본·포커스·오류 | `42_디자인_자산/components/input.png` | /verify 기관코드 입력 |
| B3 | 카드 | PNG | `42_디자인_자산/components/card.png` | 02·03 카드, 계정 카드 |
| B4 | 반경·그림자 값 | 메모 | `43_타이포.md`에 함께 | 토큰 `--radius-*`, `--shadow-*` |
| B5 | Hero 캐릭터 포즈 | 배경 투명 PNG | `42_디자인_자산/character/posture/` 중 지정 | 01 `hero` |

B1~B3은 값이 아니라 **모양을 눈으로 맞추는 용도**다. 색은 이미 있으니, 모서리가 얼마나 둥근지·그림자가 있는지·눌렀을 때 어떻게 변하는지만 보면 된다.

B5는 새로 받을 필요가 없다. `posture/main_01.png`부터 `main_06.png`까지 이미 있고, 그중 하나를 고르기만 하면 된다.

### C. 이미 있는 것 — 다시 받지 않는다

| 자산 | 위치 | 비고 |
| --- | --- | --- |
| 색상 팔레트 | `41_앱_색상.md` | Neutral, Label, Primary, Line, Background, Status, Dimmer |
| 캐릭터 | `42_디자인_자산/character/` | 감정, 미니, 포즈, 리워드 |
| 기능 이미지 | `42_디자인_자산/images/` | `004_feature-1~6`, `002_question-1~4` |
| 편지봉투 | `42_디자인_자산/images/weedool-envelope.png` | 01 `hero` |
| 배너·톤앤무드 | `42_디자인_자산/brand/` | 시안 분위기 참고 |
| 설치 QR | `public/store/qr-ios.png`, `qr-android.png` | 실물 |

색상은 앱 팔레트가 그대로 정본이라 Figma에서 색 변수를 따로 받지 않는다.

### D. Figma 밖에서 받을 것

| 항목 | 지금 상태 | 필요한 이유 |
| --- | --- | --- |
| 앱 스토어 URL 2개 | `src/config/links.ts`가 플레이스홀더 | 06 `install` 버튼, 계정 PNG 안의 QR과 짝을 이룸 |

A가 다 들어오면 9-3으로 넘어간다. B·D는 9-4 구현 전까지 받으면 된다.

## 9-3. 시안 고르기

`/impeccable shape`로 시각 방향을 2~3개 만든다. 각 안에 다음이 들어간다.

- 대표 화면 2장: `/verify`, `/welcome` 첫 두 섹션
- 색 사용 규칙: 주색을 어디에 얼마나 쓰는가
- 타이포 스케일: 제목·본문·캡션
- 캐릭터 사용 정도: 전면에 쓰는가, 보조로만 쓰는가

세 안을 나란히 두고 runway·산타 토익과 비교한 기록을 남긴다. 고른 결과와 고르지 않은 이유까지 **시안 비교 기록**에 적는다. 나중에 "왜 이 색인가"를 다시 묻게 되기 때문이다.

## 9-4. 적용 순서

순서를 지킨다. 섹션부터 손대면 같은 값을 여덟 번 고치게 된다.

| 순서 | 대상 | 하는 일 |
| --- | --- | --- |
| 1 | `src/app/globals.css` | 색·타이포·간격·반경 토큰을 정본 자산 기준으로 다시 정의 |
| 2 | `src/components/ui/`, `SectionWrapper` | 버튼·입력창·카드·섹션 틀 |
| 3 | `/verify` | 화면 하나로 토큰과 컴포넌트를 검증 |
| 4 | `/welcome` | Header → 01~07 섹션 → Footer |

토큰 이름은 앱 팔레트의 이름을 그대로 가져온다. `label-primary`, `primary-normal`, `background-alternative`처럼 쓰면 앱과 웹을 대조하기 쉽다.

정적 화면이 다 끝난 뒤에 모션을 붙인다. 순서를 뒤집으면 움직이는 화면에서 여백을 재게 된다.

## 9-5. 모션

| 대상 | 움직임 | `prefers-reduced-motion` 대체 |
| --- | --- | --- |
| 01 Hero | 편지 도착 | 최종 상태를 정지 화면으로 표시 |
| 섹션 진입 | 아래에서 살짝 올라오며 나타남 | 즉시 표시 |
| 버튼 | 눌림 반응 | 색 변화만 |
| FAQ | 펼침·접힘 | 즉시 전환 |

`prefers-reduced-motion` 대체는 선택이 아니다. 접근성 점검 항목이다.

```css
@media (prefers-reduced-motion: reduce) {
  /* 움직임을 없애되 최종 상태는 보이게 둔다 */
}
```

## 9-6. 엣지 케이스 화면

오류 화면도 디자인 대상이다. 네 가지를 만들고, 각각 어떻게 다시 불러낼 수 있는지 함께 적는다.

| 상태 | 화면 | mock 재현 |
| --- | --- | --- |
| 기관코드 오류 | 입력칸 아래 오류 문구, 입력값 유지 | 정해 둔 오류용 기관코드 입력 |
| 발급 실패 | 오류 안내와 재시도 버튼 | mock 설정으로 실패 응답 |
| PNG 다운로드 실패 | 「이미지로 저장」 버튼으로 다시 받도록 안내 | mock 설정으로 실패 |
| 네트워크 오류 | 연결 오류 문구와 재시도 | 개발자 도구에서 오프라인 |

재현 방법은 접근성 검증 리포트에 적어 둔다. 적어 두지 않으면 다음 사람이 오류 화면을 볼 방법이 없다.

## 9-7. 디자인 기준선

디자인 단계에서 이미 지켜야 하는 수치다. 10번에서 검증만 하려면 여기서 맞춰 둔다.

| 항목 | 기준 |
| --- | --- |
| 본문 글자 | 18px 이상 |
| 버튼 글자 | 20px 이상 |
| 터치 영역 | 48px 이상 |
| 글자 대비 | 4.5:1 이상 |
| 포커스 | 마우스 없이 이동할 때 테두리가 보인다 |
| 줄바꿈 | `word-break: keep-all` |

주색(`#008EFF` 계열)을 흰 글자 배경으로 쓰면 대비가 아슬아슬하다. 버튼 배경으로 쓸 때는 Strong이나 Heavy 단계를 쓴다. 그래도 걸리는 자리는 위치와 사유를 리포트에 적고 예외로 둔다.

## 9-8. DESIGN.md 남기기

구현이 끝난 뒤 `/impeccable document`로 저장소 루트에 `DESIGN.md`를 만든다. 의도가 아니라 **실제 코드에 들어간 값**을 적는다. `globals.css`의 토큰과 `DESIGN.md`의 값이 다르면 둘 중 하나가 틀린 것이다.
