## 1. 페이지 구성

화면은 둘이다. 기관코드 확인 화면이 먼저 나오고, 확인되면 내부 페이지로 들어간다. 내부 페이지는 위에서 아래로 내려가며 보는 랜딩 페이지다.

```
[기관코드 확인 화면]           [랜딩 페이지]
┌────────────────────┐        ┌──────────────────────────┐
│ ① 기관코드         │ ─확인→ │ ② 위둘 소개              │
└────────────────────┘        │ ③ 익명성                 │
                              │ ④ 매뉴얼 다운로드        │
                              │ ⑤ 계정 발급              │
                              │ ⑥ 계정 정보 저장(PNG)    │
                              │ ⑦ 앱 설치                │
                              │ ⑧ 매뉴얼 다운로드        │
                              ├──────────────────────────┤
                              │ 푸터: 문의처             │
                              └──────────────────────────┘
```

| 화면          | #   | 섹션 id            | flowStep              |
| ------------- | --- | ------------------ | --------------------- |
| 기관코드 확인 | ①   | `org-code`         | `orgCode`             |
| 랜딩 페이지   | ②   | `intro`            | `landing`             |
| 랜딩 페이지   | ③   | `anonymity`        | `landing`             |
| 랜딩 페이지   | ④   | `manual-top`       | `manualDownload`      |
| 랜딩 페이지   | ⑤   | `account`          | `issue`               |
| 랜딩 페이지   | ⑥   | `credential-image` | `credentialDownload`  |
| 랜딩 페이지   | ⑦   | `install`          | `install`             |
| 랜딩 페이지   | ⑧   | `manual-bottom`    | `manualDownloadFinal` |

**화면 주소**

| 상황                                   | 주소                                         |
| -------------------------------------- | -------------------------------------------- |
| QR로 들어올 때 (기관코드 확인 화면)    | `https://{도메인}/verify?orgCode={기관코드}` |
| 기관코드 확인 후 (랜딩 페이지)         | `https://{도메인}/welcome`                   |
| 확인하지 않고 `/welcome`으로 들어올 때 | `/verify`로 보냄                             |
| 도메인만 입력해 `/`로 들어올 때        | `/verify`로 보냄                             |

- 루트(`/`)는 나중에 다른 용도의 페이지로 쓸 수 있도록 비워 두고, 지금은 `/verify`로 보내기만 한다
- 기관코드 확인 후에는 랜딩 페이지 주소에 파라미터를 붙이지 않는다. 확인 상태는 브라우저 안에 저장해 새로고침해도 유지한다

## 2. 섹션 구현 원칙 (수정·확장 대비)

UX 수정이 여러 번 일어날 것을 전제로 한다. 섹션 추가·삭제·순서 변경·문구 수정이 서로 영향을 주지 않게 나눈다.

1. **랜딩 페이지의 섹션 목록은 설정 한 곳에서 관리한다.** 순서, 표시 여부, 표시 조건(계정 발급 후 등)을 배열 하나로 정한다. 기관코드 확인 화면은 이 목록에 넣지 않고 따로 둔다. 순서를 바꾸거나 섹션을 빼는 일은 이 배열만 고친다.
2. **섹션 하나는 폴더 하나다.** 섹션마다 컴포넌트와 자기 문구 파일을 함께 둔다. 한 섹션을 고쳐도 다른 섹션 파일은 건드리지 않는다.
3. **문구는 코드와 분리한다.** 화면에 나오는 모든 글자는 문구 파일에 모은다. UX 라이팅만 고칠 때는 컴포넌트를 열지 않는다.
4. **공통 틀은 하나로 둔다.** 섹션 간격, 제목, 스크롤 위치(anchor)는 공통 섹션 래퍼가 맡는다. 간격·제목 스타일을 바꿀 때 한 곳만 고친다.
5. **흐름 상태는 한 곳에 둔다.** 기관코드 확인 여부, 발급된 계정, 만료 여부를 하나의 상태로 관리하고 섹션은 읽기만 한다. 섹션끼리 직접 값을 주고받지 않는다.
6. **서버 호출은 섹션 밖에 둔다.** 섹션은 API 함수만 부르고, mock과 실제 API는 그 함수 안에서 바꾼다.

## 3. UX 라이팅 원칙

- 동작 원리를 설명하지 않는다. 이용자는 버튼이 무엇을 하는지만 알면 된다
- 버튼으로 충분하면 문구를 쓰지 않는다
- 문장이 필요한 곳에서는 쉽고 간결히 쓴다
- 용어 고정: 기관코드, 계정, 기관, 운영사, 자가진단

아래 문구는 모두 초안이다.

## 4. 섹션별 명세

### ① 기관코드 (기관코드 확인 화면)

| 요소      | 내용                          |
| --------- | ----------------------------- |
| 입력칸    | 기관코드 6글자                |
| 버튼      | 없음                          |
| 오류      | 기관코드를 다시 확인해 주세요 |
| 연결 오류 | 잠시 후 다시 시도해 주세요    |

**동작**

- URL 파라미터 값을 입력칸에 채운다
- 6글자가 채워지면 바로 확인하고, 유효하면 랜딩 페이지로 넘어간다
- 파라미터가 없거나 틀리면 입력칸을 비워 둔다

- 기관코드 파라미터는 암복호화하지 않는다

| 항목 4 | 상담 내용은 AI 학습에 쓰지 않아요               |

### ⑤ 계정 발급

| 상태    | 요소  | 내용                             |
| ------- | ----- | -------------------------------- |
| 발급 전 | 버튼  | 계정 받기                        |
| 발급 후 | 표시  | 아이디, 비밀번호                 |
| 발급 후 | 한 줄 | 15:40까지 앱에서 로그인해 주세요 |
| 만료    | 한 줄 | 로그인 시간이 지났어요           |
| 만료    | 버튼  | 계정 재발급                      |
| 오류    | 한 줄 | 잠시 후 다시 시도해 주세요       |

**동작**

- 만료 시각은 발급 시점부터 계산하며, 프론트는 서버가 준 `account.expiresAt`을 그대로 표시한다
- 만료 시각이 지나면 아이디·비밀번호를 흐리게 바꾸고 「계정 재발급」을 보여 준다
- 다시 받으면 ⑥의 이미지도 새 계정으로 바뀐다
- 재발급은 이전 계정과 관계없이 새 계정을 받는다. 횟수 제한은 없다

### ⑥ 계정 정보 저장

계정을 받은 뒤에 나타난다.

| 요소     | 내용          |
| -------- | ------------- |
| 미리보기 | PNG 이미지    |
| 버튼     | 이미지로 저장 |

**PNG 내용:** 위둘(WeeDool), 기관코드, 아이디, 비밀번호, 앱 설치 QR(iOS, Android 따로)

**동작**

- 계정을 발급·재발급하면 PNG를 자동으로 내려받는다. 저장 위치는 브라우저의 기본 다운로드 폴더다
- 「이미지로 저장」 버튼으로 다시 내려받을 수 있다
- 내려받지 않았어도 다음 섹션으로 진행할 수 있다

## 5. mock 값

형식은 `docs/30_API_계약.md`에서 확정했다.

| 항목           | 값                                                      |
| -------------- | ------------------------------------------------------- |
| QR 파라미터 키 | `orgCode`                                               |
| 기관코드 형식  | 영문 대문자·숫자 6글자 (예: `GGCF26`)                   |
| 아이디 형식    | `wd` + 소문자·숫자 6자리, 0·o·1·l·i 제외                |
| 비밀번호 형식  | 소문자·숫자 8자리, 0·o·1·l·i 제외                       |
| expiresAt      | ISO 8601, 시간대 포함 (예: `2026-09-14T15:40:00+09:00`) |
| mock TTL       | 10분 (테스트용으로 짧게 바꿀 수 있음)                   |

| 시나리오                | 결과               |
| ----------------------- | ------------------ |
| 올바른 기관코드         | 랜딩 페이지로 이동 |
| 틀린 기관코드           | ① 오류             |
| 기관코드 확인 서버 오류 | ① 연결 오류        |
| 계정 발급 성공          | ⑤ 발급 후, ⑥ 표시  |
| 계정 발급 서버 오류     | ⑤ 오류             |
| 만료 시각 경과          | ⑤ 만료             |
