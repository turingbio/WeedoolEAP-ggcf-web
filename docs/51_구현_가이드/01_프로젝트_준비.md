## 1-2. 프로젝트 생성

### 왜 하위 폴더에 만드는가

`create-next-app`은 폴더 이름으로 패키지 이름을 정한다. 지금 폴더 이름 `WeedoolEAP-ggcf-web`에는 **대문자**가 있는데, 패키지 이름에는 대문자를 쓸 수 없어 현재 폴더(`.`)에 바로 만들면 실패한다. 그래서 소문자 이름의 하위 폴더에 만든 뒤 파일을 위로 옮긴다.

또 `create-next-app`은 `CLAUDE.md`를 새로 만든다. 옮길 때 기존 `CLAUDE.md`를 덮어쓰지 않도록 이름을 먼저 바꿔 둔다.

### 순서

**① 기존 CLAUDE.md 이름 바꾸기**

`CLAUDE.md`는 아직 커밋되지 않은 파일이라 `git mv`가 아니라 일반 `mv`를 쓴다.

```bash
mv CLAUDE.md CLAUDE.ouroboros.md
```

**② 하위 폴더에 생성**

```bash
pnpm create next-app@latest weedool-ggcf-web
```

질문이 차례로 나온다. 화살표 키로 고르고 Enter를 누른다.

| 질문                                                    | 선택                       |
| ------------------------------------------------------- | -------------------------- |
| Would you like to use the recommended Next.js defaults? | **No, customize settings** |
| TypeScript                                              | **Yes**                    |
| Which linter would you like to use?                     | **ESLint**                 |
| React Compiler                                          | **No**                     |
| Tailwind CSS                                            | **Yes**                    |
| `src/` directory                                        | **Yes**                    |
| App Router                                              | **Yes**                    |
| Turbopack                                               | **Yes**                    |
| Cache Components                                        | **No**                     |
| customize the import alias                              | **No** (기본값 `@/*` 사용) |
| AGENTS.md                                               | **Yes**                    |

질문 문구나 순서는 버전에 따라 조금 다를 수 있다. 위 표의 의미대로 고른다.

설치 끝에 `Ignored build scripts: ...` 경고가 나오면 아래를 실행하고, 목록에 나온 패키지를 모두 선택해 승인한다.

```bash
cd weedool-ggcf-web
pnpm approve-builds
cd ..
```

**③ 파일을 위로 옮기기**

```bash
shopt -s dotglob
mv weedool-ggcf-web/* .
shopt -u dotglob
rmdir weedool-ggcf-web
```

- `shopt -s dotglob`은 `.gitignore`처럼 점으로 시작하는 파일도 함께 옮기게 한다
- `mv`가 「이미 있다」며 멈추는 파일이 있으면 그 파일 이름을 알려 달라

**④ 설치 다시 확인**

폴더를 옮기면 일부 링크가 깨질 수 있으니 한 번 더 설치한다.

```bash
pnpm install
```

### CLAUDE.md 합치기

1. 새로 생긴 `CLAUDE.md`를 연다
2. `CLAUDE.ouroboros.md`에서 `<!-- ooo:START -->`부터 `<!-- ooo:END -->`까지 복사해 새 `CLAUDE.md` 맨 끝에 붙인다
3. 그 아래에 프로젝트 규칙을 추가한다

```markdown
## 프로젝트 규칙

- 기준 문서: docs/11_seed.yaml, docs/20_기획_화면흐름_초안.md, docs/30_API_계약.md
- 화면 용어: 기관코드, 계정, 기관, 운영사, 자가진단
- 코드와 문서에서 institution이라는 이름을 쓰지 않고 org를 쓴다
- 화면 문구는 각 섹션의 content.ts와 src/content에만 둔다
- 개인정보(이름, 연락처, 부서 등)를 받거나 보내는 코드를 만들지 않는다
```

4. `CLAUDE.ouroboros.md`를 지운다 (커밋된 적 없는 파일이라 `git rm`이 아니라 `rm`)

```bash
rm CLAUDE.ouroboros.md
```

### 실행

```bash
pnpm dev
```

브라우저에서 `http://localhost:3000`을 연다. Next.js 기본 화면이 보이면 성공이다. `Ctrl + C`로 끈다.

### 생긴 파일 훑어보기

| 파일                  | 역할                                               |
| --------------------- | -------------------------------------------------- |
| `package.json`        | 설치한 라이브러리와 명령어(`dev`, `build`, `lint`) |
| `next.config.ts`      | Next.js 설정                                       |
| `tsconfig.json`       | TypeScript 설정. `@/*` 경로가 여기 있다            |
| `eslint.config.mjs`   | ESLint 설정                                        |
| `postcss.config.mjs`  | Tailwind 연결 설정                                 |
| `src/app/layout.tsx`  | 전체 틀                                            |
| `src/app/page.tsx`    | `/` 화면                                           |
| `src/app/globals.css` | 전역 CSS와 Tailwind                                |
| `public/`             | 정적 파일                                          |

### 커밋

구현 가이드(`docs/`)는 빼고 나머지를 모두 올린다. 이 가이드의 모든 커밋은 이 형태를 쓴다.

```bash
git add -A -- . ':!docs'
git status
git commit -m "chore: Next.js 프로젝트 생성"
```

- `':!docs'`: `docs` 폴더는 빼라는 뜻이다. 작은따옴표까지 그대로 친다
- `git status`에서 `docs/guide/`, `docs/50_구현_가이드.md`, 이미지가 **커밋 대상(초록색)에 없는지** 확인한 뒤 커밋한다
- 기획 문서를 고쳐 커밋해야 할 때는 `git add docs/20_기획_화면흐름_초안.md`처럼 파일을 직접 지정한다

**확인:** `pnpm dev`로 기본 화면이 뜨고, `package.json`의 `name`이 `weedool-ggcf-web`이다.

## 1-3. Prettier

코드 모양(들여쓰기, 따옴표, Tailwind 클래스 순서)을 자동으로 맞춘다.

### 설치

```bash
pnpm add -D prettier prettier-plugin-tailwindcss
```

`-D`는 개발할 때만 쓰는 도구라는 뜻이다.

### 설정 파일

프로젝트 맨 위에 `.prettierrc`를 만든다.

```json
{
  "singleQuote": true,
  "semi": true,
  "trailingComma": "all",
  "printWidth": 100,
  "plugins": ["prettier-plugin-tailwindcss"],
  "tailwindStylesheet": "./src/app/globals.css"
}
```

- `tailwindStylesheet`: Tailwind 4는 설정을 CSS 파일에 두기 때문에, 플러그인에 그 파일 위치를 알려 준다

`.prettierignore`도 만든다.

```
.next
node_modules
pnpm-lock.yaml
```

### 명령어 추가

`package.json`의 `"scripts"` 안에 `format`을 추가한다.

```json
{
  "scripts": {
    "dev": "...그대로...",
    "build": "...그대로...",
    "start": "...그대로...",
    "lint": "...그대로...",
    "format": "prettier --write ."
  }
}
```

기존 줄은 건드리지 않고 `format` 한 줄만 추가한다. 앞 줄 끝에 쉼표를 빠뜨리지 않는다.

```bash
pnpm format
```

**확인:** 오류 없이 파일 목록이 출력된다.

## 1-5. 환경 변수

### .gitignore 먼저 고치기

`create-next-app`이 만든 `.gitignore`에는 `.env*`가 들어 있어 **`.env.example`까지 무시**된다. `.gitignore`에서 `.env*` 줄 바로 아래에 한 줄을 추가한다.

```
.env*
!.env.example
```

`!`는 「이 파일은 예외로 커밋한다」는 뜻이다.

### .env.example (커밋함)

어떤 값이 필요한지 알려 주는 견본이다.

```
# 실제 서버 주소. 서버가 준비되기 전에는 비워 둔다
NEXT_PUBLIC_API_BASE_URL=

# true면 mock 사용, false면 실제 서버 사용
NEXT_PUBLIC_USE_MOCK=true

# mock에서 통과시킬 기관코드 (6글자)
NEXT_PUBLIC_MOCK_VALID_ORG_CODE=GGCF26

# mock 계정 만료까지 걸리는 초. 만료 화면을 볼 때는 30 등으로 줄인다
NEXT_PUBLIC_MOCK_TTL_SECONDS=600
```

### .env.local (커밋 안 함)

`.env.example`을 복사해 실제로 쓸 값을 둔다.

```bash
cp .env.example .env.local
```

값을 바꾼 뒤에는 **개발 서버를 껐다 켠다.**

### 커밋

```bash
pnpm format
git add -A -- . ':!docs'
git commit -m "chore: Prettier, html-to-image, 환경 변수 견본 추가"
```

**확인:** `git status`에 `.env.local`이 보이지 않고, `.env.example`은 커밋되었다.
