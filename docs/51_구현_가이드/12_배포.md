# 12. 배포

목표: 웹사이트를 실제 주소로 띄운다. mock 시연본을 먼저 올려 구성을 확인받고, 백엔드가 준비되면 같은 프로젝트의 환경 변수만 바꿔 운영 배포로 넘어간다.

`docs/42_디자인_배포_인계.md` 4장이 배포를 두 단계로 나눠 두었다. 이 문서는 그 두 단계를 따른다.

---

## 12-1. 두 단계로 나누는 이유

| 단계 | 상태                                     | 보여 주는 것                  |
| ---- | ---------------------------------------- | ----------------------------- |
| 1    | `NEXT_PUBLIC_USE_MOCK=true`              | 화면 구성, 문구, 디자인, 흐름 |
| 2    | `NEXT_PUBLIC_USE_MOCK=false` + 서버 주소 | 실제 기관코드와 계정 발급     |

1단계는 백엔드를 기다리지 않고 진행한다. 의뢰자가 화면을 먼저 보고 구성을 확정하면, 뒤에 고칠 일이 줄어든다.

1단계 주소는 외부에 알리지 않는다. mock 기관코드로 아무나 계정 화면까지 들어갈 수 있고, 그 계정은 앱에서 쓸 수 없어 혼란을 준다. 링크를 아는 사람만 보는 미리보기로 둔다.

---

## 12-2. Vercel 연결

1. [vercel.com](https://vercel.com)에 GitHub 계정으로 로그인한다
2. Add New → Project에서 이 저장소를 고른다
3. Framework Preset이 Next.js로 잡히는지 확인한다. 빌드 명령과 출력 경로는 손대지 않는다
4. 패키지 매니저는 `pnpm-lock.yaml`을 보고 pnpm으로 잡힌다

`next.config.ts`의 `allowedDevOrigins`는 개발 서버 전용이라 배포에는 영향이 없다.

### 브랜치와 배포 환경

| 브랜치         | Vercel 환경 | 쓰임                        |
| -------------- | ----------- | --------------------------- |
| `main`         | Production  | 실제 주소                   |
| 그 밖의 브랜치 | Preview     | PR마다 생기는 미리보기 주소 |

`dev`에서 작업하고 `main`에 병합할 때 운영 배포가 나가는 흐름이 된다. 1단계 시연은 `dev`의 Preview 주소로 보여 주면 운영 주소를 건드리지 않는다.

---

## 12-3. 환경 변수

`.env.local`은 저장소에 올라가지 않는다(`.gitignore`가 `.env*`를 막는다). Vercel 대시보드의 Settings → Environment Variables에 직접 넣어야 한다.

| 변수                              | Preview(1단계) | Production(2단계) |
| --------------------------------- | -------------- | ----------------- |
| `NEXT_PUBLIC_USE_MOCK`            | `true`         | `false`           |
| `NEXT_PUBLIC_API_BASE_URL`        | 비움           | 실제 서버 주소    |
| `NEXT_PUBLIC_MOCK_VALID_ORG_CODE` | `GGCF26`       | 비움              |
| `NEXT_PUBLIC_MOCK_TTL_SECONDS`    | `600`          | 비움              |
| `NEXT_PUBLIC_SITE_URL`            | 비움           | 배포 주소         |
| `NEXT_PUBLIC_GA_ID`               | 비움           | GA4 측정 ID       |

`NEXT_PUBLIC_` 변수는 빌드할 때 번들에 박힌다. 값을 바꾸면 반드시 다시 배포해야 하고, 대시보드에서 고치는 것만으로는 바뀌지 않는다. Deployments에서 Redeploy를 누른다.

이 값들은 모두 브라우저로 내려간다. 비밀 값을 `NEXT_PUBLIC_` 이름으로 두면 안 된다. 지금 쓰는 여섯 개는 모두 공개돼도 되는 값이다.

`NEXT_PUBLIC_GA_ID`는 Preview에 넣지 않는다. 시연하며 누른 클릭이 실제 지표에 섞인다.

---

## 12-4. 도메인과 CORS

도메인을 붙이면 CORS 허용 목록을 백엔드에 알려야 한다. `docs/30_API_계약.md` 2장 나절의 운영 Origin 칸이 "도메인 확정 후 전달"로 비어 있다.

1. Vercel Settings → Domains에서 도메인을 추가하고 DNS 레코드를 등록한다
2. 확정된 주소를 `30_API_계약.md`의 CORS 표에 적는다
3. 백엔드에 그 주소를 전달하고, 서버에 반영됐는지 확인한다
4. 배포된 화면에서 기관코드를 넣어 보고 Console에 CORS 오류가 없는지 본다

Vercel은 배포마다 임시 주소를 새로 만든다. 그 주소까지 일일이 허용 목록에 넣을 수는 없으므로, 백엔드 연동을 확인할 때는 고정 도메인이나 브랜치 고정 주소를 쓴다.

## 12-5. 공유와 검색

### 정한 것

검색 수집은 받지 않는다. 기관 직원이 QR과 사내 공지로만 들어오는 사이트라, 검색으로 모르는 사람이 유입돼도 기관코드에서 막힐 뿐이다. `src/app/robots.ts`가 전체를 막는다.

```ts
import type { MetadataRoute } from 'next';

export default function robots(): MetadataRoute.Robots {
  return {
    rules: { userAgent: '*', disallow: '/' },
  };
}
```

`layout.tsx`의 `metadata`에도 `robots: { index: false, follow: false }`를 둔다. `robots.txt`를 읽지 않는 수집기에 대비해 두 곳 모두에 적는다.

검색에 노출하지 않으므로 `sitemap.xml`은 만들지 않는다.

메신저 공유 카드는 쓴다. 사내 공지로 링크를 돌릴 때 무엇인지 보이는 편이 낫다. 문구는 `commonContent.meta`에 두고 `openGraph`가 그 값을 쓴다.

| 필드          | 값                                                                |
| ------------- | ----------------------------------------------------------------- |
| `title`       | 이름 없이 시작하는 마음 관리 \| 위둘 EAP                          |
| `description` | 기관이 준비한 AI 마음 관리 앱입니다. 이름도 연락처도 묻지 않아요. |
| `siteName`    | 위둘 EAP                                                          |
| `locale`      | `ko_KR`                                                           |

제목을 이렇게 정한 이유는 이 서비스의 가장 큰 걱정거리를 먼저 풀기 위해서다. 회사가 알게 될까 불안한 사람에게 제목만으로 답이 된다. 브라우저 탭에서는 앞 15자 정도만 보여 브랜드명이 잘리지만, 탭 제목보다 공유 카드에서 읽히는 쪽이 중요하다고 봤다.

### 배포 주소를 반드시 넣는다

`metadataBase`는 `NEXT_PUBLIC_SITE_URL`로 받는다. 이 값이 없으면 Next가 기본값을 써서 `og:image`가 `http://localhost:3000/og.png`로 나간다. 그 주소로는 메신저가 이미지를 받아올 수 없어 카드에 그림이 뜨지 않는다.

배포된 화면의 HTML을 열어 `og:image` 값이 실제 도메인으로 시작하는지 확인한다.

### 공유 카드 이미지

`public/og.png`(1200×630)를 쓴다. Hero와 같은 종이 배경 위에 로고와 제목을 얹어, 카드에서 본 장면이 들어와서도 이어지게 했다.

이미지는 화면을 캡처해 만들었다. 문구나 로고가 바뀌면 같은 방법으로 다시 만든다.

1. `src/app/og-preview/page.tsx`에 1200×630 크기의 카드 화면을 임시로 만든다. 최상위 요소에 `id="og-card"`를 준다
2. `pnpm dev`로 띄우고 `/og-preview`를 연다
3. 브라우저 뷰포트를 1200×630으로 맞추고 개발 표시를 지운 뒤 그 요소만 캡처한다

```bash
B="$HOME/.claude/skills/gstack/browse/dist/browse"
$B viewport 1200x630
$B goto http://localhost:3000/og-preview
$B js "document.querySelectorAll('nextjs-portal').forEach(function(e){e.remove()})"
$B screenshot --selector "#og-card" public/og.png
```

4. 캡처가 끝나면 임시 화면을 지운다

브라우저로 찍는 이유는 글꼴 때문이다. `opengraph-image.tsx`로 코드에서 만들면 이미지 생성기가 woff2를 읽지 못하는데, 가진 글꼴이 `PretendardVariable.woff2` 하나뿐이다. 글꼴을 지정하지 못하면 서버 환경의 글꼴로 그리는데, 배포 환경에 한글 글꼴이 없으면 글자가 네모로 깨진다. 로컬에서는 멀쩡해 보이고 배포 후에만 깨지므로 알아채기도 늦다. 브라우저는 woff2를 그대로 읽으니 이 문제가 없다.

카카오톡은 카드 비율에 따라 가장자리를 잘라 내고 때로 정사각형으로 보여 준다. 로고와 글자는 왼쪽 630px 안에 모아 둔다.

## 12-6. 배포 후 확인

배포된 주소에서 10번 문서의 완료 시나리오를 다시 돈다. 로컬에서 통과한 것이 배포 환경에서 깨지는 경우가 있다.

| 확인할 것 | 보는 법                                      | 깨지는 이유                             |
| --------- | -------------------------------------------- | --------------------------------------- |
| 환경 변수 | mock 기관코드가 의도대로 통과하거나 막히는지 | Vercel에 값을 안 넣었거나 재배포 누락   |
| 이미지    | 로고·QR·앱 캡처가 모두 보이는지              | 파일명 대소문자. 로컬은 구분하지 않는다 |
| 글꼴      | Pretendard가 적용됐는지                      | `src/app/fonts/` 경로 문제              |
| 계정 PNG  | 저장된 이미지에 QR이 들어가는지              | 외부 주소 이미지를 쓰면 빠진다          |
| HTTPS     | 주소창 자물쇠                                | 도메인 DNS 설정                         |
| 모바일    | 실기기에서 PNG 자동 다운로드                 | 브라우저 정책                           |

파일명 대소문자는 특히 자주 걸린다. Windows는 `Logo.png`와 `logo.png`를 같게 보지만 Vercel의 리눅스 환경은 다르게 본다. 로컬에서 보이던 이미지가 배포 후에만 깨지면 먼저 이것을 의심한다.

---

## 12-7. 되돌리기

배포한 화면에 문제가 생기면 코드를 고쳐 다시 배포하기 전에 이전 버전으로 되돌린다.

Vercel의 Deployments 목록에서 정상이던 배포를 고르고 Promote to Production을 누른다. 빌드를 다시 하지 않아 수십 초 안에 끝난다. 원인은 되돌린 뒤에 찾는다.
