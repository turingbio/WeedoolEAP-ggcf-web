# 8. 화면 구성과 UX 라이팅

목표: 7번에서 동작하게 만든 화면의 구성과 문구를 확정한다. 섹션의 순서와 역할을 정하고, 용어와 제목 규칙을 세우고, 문구를 다 쓴 뒤, 그 문구를 `content.ts`로 옮겨 `docs/21_UX_문구.md`와 코드를 같은 상태로 맞춘다.

- 기준 문서: `docs/21_UX_문구.md`
- 근거 문서: `docs/90_archive/UX_문구_시안.md`

## 8-1. 구성

### 유저의 의식 흐름 반영

섹션별로 사용자가 마주했을 때 가질 수 있는 의문과 그에 대한 단일 문장 형태의 답변을 정의한다. 해당 표는 제목 작성의 평가 기준이 된다.

| 섹션         | 독자 질문                   | 답                                   |
| ------------ | --------------------------- | ------------------------------------ |
| 01 Hero      | 이게 뭐지? 누가 보냈지?     | 기관이 보낸, 나만 쓰는 마음 관리 앱  |
| 02 소개      | 그래서 뭘 해 주는데?        | 언제든 털어놓고, 점검하고, 돌본다    |
| 03 익명성    | 회사가 알게 되면 어떡하지?  | 누구도 내가 누군지 모른다            |
| 04 계정      | 가입이 번거롭지 않을까?     | 개인정보 없이 바로 받는다            |
| 05 프로세스  | 앱에 들어가면 뭘 하지?      | 로그인부터 리포트까지 다섯 단계      |
| 06 설치      | 어디서 받지?                | QR이나 스토어 버튼                   |

## 8-3. 용어 표준화

동일한 개념에 서로 다른 용어를 혼용하면 기능 분산으로 오인될 수 있으므로 단일 표준 용어로 통일한다.

| 지양하는 용어                | 표준 용어       |
| ---------------------------- | --------------- |
| 정서 통합 문진, 문진         | 자가진단        |
| 업무 스트레스                | 직무 스트레스   |
| 유저                         | 이용자          |
| 트래킹                       | 추적            |
| institution                  | org             |

`기관코드`, `계정`, `기관`, `운영사`, `사용자 매뉴얼`도 고정 용어로 관리한다.

## 8-4. 제목 작성 규칙

### 3계층 구조

| 층위   | 역할                        | 길이                  | 예시                                                                      |
| ------ | --------------------------- | --------------------- | ------------------------------------------------------------------------- |
| 라벨   | 이 섹션이 무엇인지          | 명사구, 14자 이내     | 기관 직원 전용 AI 멘탈케어                                                |
| 제목   | 독자 질문에 대한 답변       | 모바일 기준 2줄 이내  | 위둘 EAP가 털어놓기 어려운 마음, 언제 어디서나 들어드려요                 |
| 설명   | 제목을 뒷받침하는 근거·숫자 | 단일 행               | 79,500건의 실제 상담 데이터로 학습한 AI와 임상 검증된 행동활성화 프로그램 |

라벨과 설명은 필요한 섹션에만 둔다.

### 다각도 시안 도출

단일 문장을 반복해서 다듬는 방식은 표현력 개선에 한계가 있다. 공감, 약속, 수치, 질문, 반전, 명사형 등의 관점을 설정하여 5~8개의 시안을 도출한 뒤 비교 후 채택한다.

```

원안  앱에서 사용할 계정을 받아 보세요
명사  나만 아는 익명 계정
반전  가입 없이, 이름 없이 시작해요
행동  먼저 계정을 생성해 주세요        ← 채택

```

### 금지 사항

- 느낌표, "압도적인", "최고의" 등의 과장 표현
- 성과를 단정하는 개선율 수치 (예: 우울감 82% 개선)
- 동작 원리 서술 (예: "버튼을 누르면 계정이 만들어집니다" 형태의 설명 배제)
- 버튼 자체로 의미 전달이 충분한 영역의 안내 문구

### 어미 다양화

모든 제목이 ~해 보세요 형태로 끝나면 UI 리듬감이 단조로워진다. 명사형, 해요체, 합니다체, 의문문을 적절히 조합한다.

## 8-5. 상태별 문구 정의

단일 섹션이 내부 상태에 따라 분기될 경우, 상태 정의를 선행하고 하위에 대응 문구를 매핑한다.

| 상태     | 문구                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 발급 전  | 계정 발급받기                                                                                                                                                  |
| 발급 중  | 계정을 생성하고 있어요                                                                                                                                         |
| 발급 후  | HH:mm 전까지 앱에서 로그인을 완료해 주세요. / 계정 정보 카드가 다운로드 폴더에 저장되었어요. / 익명 계정은 복구가 불가능하니 저장된 이미지를 꼭 보관해 주세요. |
| 오류     | 일시적인 오류로 계정을 생성하지 못했어요. + 재시도하기                                                                                                         |

`/verify` 화면의 오류 문구는 기관코드 오입력, 네트워크 단절, 기타 예외의 3가지 유형으로 분기하여 `common.ts`에 정의한다. 입력 필드의 플레이스홀더(placeholder)는 빈 값('')으로 유지한다. QR 진입 시 자동으로 값이 주입되며 6자리 완성 즉시 검증이 수행되므로 이 동작을 별도의 안내 텍스트로 설명하지 않는다.

### 실패/불가 안내 패턴

예외 상황이나 불가 사유를 안내할 때는 이유를 먼저 제시하고 정중하고 완곡한 어조를 적용한다. 통보 형태를 지양한다.

```
나쁨  계정은 다시 찾을 수 없습니다.
좋음  비식별 계정이라 다시 찾아 드리기 어려운 점 양해 부탁드립니다.
      페이지를 새로고침하시면 새 계정을 발급받으실 수 있어요.
```

## 8-6. 텍스트 리소스 관리 규칙

### 원칙

화면에 렌더링되는 모든 텍스트는 `src/sections/*/content.ts` 및 `src/content/common.ts` 내부에만 정의한다. 컴포넌트(.tsx) 파일 내부에 한국어 문자열을 직접 하드코딩하지 않는다. 단일 문서 수정으로 코드베이스의 문구가 일괄 반영되도록 구조를 분리한다.

| 콘텐츠 성격                             | 파일 경로                                   |
| --------------------------------------- | ------------------------------------------- |
| 특정 섹션 전용 문구                     | `src/sections/<id>/content.ts`              |
| 공용/전역 문구                          | `src/content/common.ts`                     |
| 화면 전용 문구                          | `src/features/org-code/content.ts`          |
| 계정 PNG 내부 텍스트                    | `src/sections/credential-image/content.ts`  |
| 주소·링크                               | `src/config/links.ts`                       |

### 네이밍 컨벤션

문서의 층위 명칭을 그대로 사용하여 문서와 코드 간의 매핑 가시성을 확보한다.

```ts
export const introContent = {
  label: '기관 직원 전용 AI 멘탈케어',
  title: '...',
  body: '...',
  features: [{ label: '...', title: '...', description: '...' }],
} as const;
```

인터랙션 버튼은 `issueButton`, `retryButton`과 같이 후위 명칭으로 `Button`을 붙이고, 이미지 대체 텍스트는 `envelopeAlt`, `iosQrAlt`와 같이 `Alt`를 명시한다.

### 동적 값 삽입 패턴

서버로부터 전달받은 변수가 포함되는 텍스트는 문자열 결합 연산 방식 대신 함수 형태로 선언한다.

```ts
loginUntil: (time: string) => `${time} 전까지 앱에서 로그인을 완료해 주세요.`,
```
