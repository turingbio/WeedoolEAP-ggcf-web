# 11. 백엔드 연동

목표: mock으로 개발한 화면을 실제 서버에 붙인다.

기준 문서는 `docs/30_API_계약.md` v0.4다. v0.3까지는 프론트엔드 mock을 기준으로 쓴 안이었고, 실제 서버는 이미 다른 형태로 구현되어 있었다. 지금은 서버가 기준이고 프론트엔드가 맞춘다.

---

## 11-1. 서버와 다른 점

mock과 실제 서버의 차이가 커서 API 계층을 고쳤다. 화면 코드는 그대로 두고 `src/lib/api/` 안에서만 변환한다.

| 항목          | mock 기준 설계            | 실제 서버                              |
| ------------- | ------------------------- | -------------------------------------- |
| 기관코드 확인 | `POST /api/org/verify`    | `GET /orgs/v1/{orgCd}/validate`        |
| 확인 결과     | `valid`                   | `data.exists`                          |
| 계정 발급     | `POST /api/accounts`      | `POST /non-identify/accounts/v1/issue` |
| 요청 필드     | `orgCode`                 | `orgCd`                                |
| 응답 형태     | 필드 직접                 | `{ code, message, data, detailCode }`  |
| 계정 아이디   | `accountId` (짧은 문자열) | `email` (이메일 형식)                  |
| 만료          | `expiresAt` 절대 시각     | `ttl` 남은 초                          |

### 응답 래퍼 벗기기

`src/lib/api/client.ts`가 래퍼를 처리한다. `getJson`과 `postJson`은 `data`만 꺼내 돌려주므로, 부르는 쪽은 래퍼를 몰라도 된다.

실패 판정은 `detailCode`로 한다. 값이 없으면 `code`를 문자열로 쓴다.

### 만료 시각 만들기

서버가 남은 초만 보내므로 `src/lib/api/accounts.ts`의 `toAccount`가 응답을 받은 시각에 더해 `expiresAt`을 만든다. 화면은 지금까지처럼 `account.expiresAt`만 본다.

이 계산은 이용자 기기의 시계를 쓴다. 시계가 틀린 기기에서는 만료 시각도 함께 틀어진다. 서버가 절대 시각을 함께 보내 주면 없앨 수 있는 문제라 계약서 6장에 요청 항목으로 적어 두었다.

### 응답 검증

`toAccount`는 `email`·`password`·`ttl`의 타입을 확인하고, 하나라도 어긋나면 `ApiError('SERVER_ERROR')`를 던진다. 서버가 필드를 빠뜨렸을 때 계정 카드가 빈 값으로 그려지는 것을 막는다.

---

## 11-2. 백엔드에 요청할 것

연동을 끝내려면 서버 쪽 작업 두 가지가 필요하다. 프론트엔드 코드로는 풀 수 없다.

### CORS 허용

2026-09-22 기준 막혀 있다. `Origin` 헤더를 붙여 요청하면 403이 온다.

```bash
curl -s -D - -o /dev/null -H "Origin: http://localhost:3000" \
  "https://lifeapi.weedool.com:8071/orgs/v1/GGCF26/validate"
```

`access-control-allow-origin` 헤더가 응답에 없으면 브라우저가 막는다. curl은 CORS를 따지지 않으므로 응답이 오는 것만으로는 판단할 수 없다.

계정 발급은 `Content-Type: application/json`을 써서 브라우저가 `OPTIONS`를 먼저 보낸다. 그 요청도 통과해야 한다.

### 기관코드 등록

`GGCF26`으로 조회하면 `exists: false`가 온다. 아직 서버에 없다. 실제 기관코드를 등록하고 값을 받아야 한다.

---

## 11-3. 전환하기

서버 준비가 끝나면 `.env.local`을 고치고 개발 서버를 껐다 켠다. `NEXT_PUBLIC_` 변수는 빌드 시점에 번들로 들어가므로 재시작하지 않으면 반영되지 않는다.

```
NEXT_PUBLIC_USE_MOCK=false
NEXT_PUBLIC_API_BASE_URL=https://lifeapi.weedool.com:8071
```

주소 끝에 `/`를 붙이면 요청 경로가 `//orgs/...`가 된다.

---

## 11-4. 오류 문구 분기

`src/lib/api/errors.ts`의 `toErrorKind`가 `detailCode`를 보고 두 갈래로 나눈다.

| 갈래             | detailCode                        | 화면 문구                                    |
| ---------------- | --------------------------------- | -------------------------------------------- |
| `invalidOrgCode` | `ORG003`, `CONTRACT001`, `CMN002` | 「기관코드를 다시 확인해 주세요」            |
| `other`          | 그 밖의 모든 코드, 네트워크 오류  | 「일시적인 오류로 계정을 생성하지 못했어요」 |

`AccountSection`이 이 값을 받아 문구를 고른다. mock에서는 기관코드 확인을 통과한 코드로만 발급을 요청하므로 첫 갈래가 거의 나오지 않아 눈에 띄지 않았다. 실제 서버에서는 확인과 발급 사이에 기관 계약이 바뀌면 나온다.

### 아직 정하지 못한 문구

`CONTRACT005`(계약 인원 초과), `CONTRACT008`(서비스 기간이 아님), `CONTRACT004`(유효하지 않은 계약)는 지금 `other`로 떨어져 「잠시 후 다시 시도해 주세요」 쪽 안내를 받는다. 이 셋은 다시 시도해도 풀리지 않는 상황이라 안내가 맞지 않는다.

문구를 새로 만들려면 `docs/21_UX_문구.md`에 먼저 넣고 코드로 옮긴다. 문서가 먼저라는 8번의 순서를 여기서도 지킨다.

---

## 11-5. 연동 확인

10-3의 완료 시나리오를 실제 서버로 다시 돈다. mock에서 기관코드로 만들던 실패는 실제 서버에서 만들 수 없으므로 아래 방법을 쓴다.

| 확인할 것      | mock에서                 | 실제 서버에서                        |
| -------------- | ------------------------ | ------------------------------------ |
| 기관코드 오류  | 유효하지 않은 6글자 입력 | 같다                                 |
| 서버 오류      | `ERR500` 입력            | 개발자 도구 Network 탭을 Offline으로 |
| 네트워크 끊김  | 해당 없음                | 위와 같다                            |
| 만료 시각 표시 | TTL을 30초로 단축        | 발급 직후 표시된 시각이 15분 뒤인지  |

Network 탭에서 함께 본다.

1. 요청 주소가 `/orgs/v1/{기관코드}/validate`, `/non-identify/accounts/v1/issue`인지
2. 계정 발급 요청 본문이 `{ "orgCd": "..." }`이고 대문자로 정규화되어 있는지
3. 응답의 `data` 안에 `email`·`password`·`ttl`이 모두 있는지
4. Console에 CORS 오류가 없는지

### 화면에서 볼 것

실제 서버의 아이디는 이메일 형식이라 mock보다 훨씬 길다. 계정 정보 카드와 저장된 PNG에서 값이 잘리거나 줄바꿈으로 무너지지 않는지 320px 폭에서 확인한다. mock 값으로는 드러나지 않는 문제다.

---

## 11-6. 자주 나는 오류

| 증상                                        | 원인                              | 해결                                            |
| ------------------------------------------- | --------------------------------- | ----------------------------------------------- |
| Console에 CORS 오류가 난다                  | 서버에 Origin이 등록되지 않았다   | 백엔드에 11-2의 주소를 알려 준다                |
| 요청 주소에 `//orgs`가 들어간다             | 기본 주소 끝에 `/`가 붙었다       | 환경 변수에서 끝의 `/`를 뺀다                   |
| 정상 기관코드인데 확인에 실패한다           | 서버에 기관코드가 등록되지 않았다 | `exists` 값을 확인하고 백엔드에 등록을 요청한다 |
| 계정 발급은 되는데 만료 시각이 이상하다     | 기기 시계가 틀렸다                | 기기 시간을 자동으로 맞춘다                     |
| 기관코드를 틀렸는데 서버 오류 문구가 나온다 | `detailCode`가 11-4 표에 없다     | 표에 코드를 더한다                              |
| 환경 변수를 바꿨는데 mock이 계속 돈다       | 개발 서버를 재시작하지 않았다     | 서버를 껐다 켠다                                |
